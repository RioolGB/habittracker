# HabitTracker — личный трекер привычек

Веб-приложение по техническому заданию **ТЗ.docx** (в корне репозитория).

Стек: **React + TypeScript + Vite** (фронтенд), **Node.js + Express** (REST API),
**PostgreSQL** (БД), **Redis** (кэширование refresh-сессий), **JWT** (аутентификация),
тёмная/светлая темы, адаптивная вёрстка (mobile-first).

## Возможности (по ТЗ)

- **Лендинг** с hero-блоком, «Как это работает», возможностями, примером дашборда и преимуществами.
- **Регистрация / Вход / Восстановление пароля** (email, с fallback-ссылкой в dev).
- **Дашборд «Today»**: приветствие по времени суток, прогресс-бар «Выполнено X из Y»,
  чекбоксы и числовые поля для привычек, быстрое inline-добавление, блоки мотивации
  («Лучше, чем вчера») и «Статистика в виде пользы» (конвертация единиц).
- **Привычки**: список с фильтрами (Активные / Все / Архивные), стрики 🔥, лимит пропусков
  в месяц, прогресс недели; создание/редактирование со всеми полями ТЗ (тип, периодичность,
  дни недели, напоминание, единицы/цель, коэффициент перевода, лимит пропусков), архив,
  удаление с подтверждением.
- **Категории**: глобальные (нельзя менять/удалять) и пользовательские (CRUD).
- **Календарь**: месяц, цветовая индикация дня (зелёный/жёлтый/серый), модалка дня
  с возможностью отметить/исправить выполнение за прошлые дни.
- **Статистика привычки**: текущая и лучшая серия, проценты 7/30/90 дней, линейный график.
- **Общая статистика**: активность за всё время, топ-3 успешных и провальных привычек,
  лучший день/неделя/месяц, столбчатый график по месяцам.
- **Профиль/настройки**: личные данные, смена пароля, переключатели уведомлений
  (email/push), тема (по умолчанию тёмная), экспорт CSV, удаление всех данных.
- **404** с переадресацией на дашборд (если залогинен) или лендинг.

## Запуск

Требуется **Node.js ≥ 18** и **Docker** (для PostgreSQL + Redis). Если Docker недоступен,
можно использовать локальные PostgreSQL/Redis и указать их в `backend/.env`.

```bash
# 1. Запустить БД и Redis
docker compose up -d

# 2. Установить зависимости (корневой workspace: backend + frontend)
npm install

# 3. Инициализировать схему БД (создаёт таблицы и глобальные категории)
npm run db:init

# 4. Запустить бэкенд и фронтенд одновременно
npm run dev
```

После этого:

- Фронтенд: **http://localhost:5173**
- API (health-check): **http://localhost:5001/api/health**

`npm run dev` запускает оба через `concurrently`. Можно запускать раздельно:
`npm run dev:backend` и `npm run dev:frontend`.

Первые экраны: создайте аккаунт (Вход → Нет аккаунта?), затем добавьте привычки.

## Переменные окружения

Примеры: `backend/.env.example`, `frontend/.env.example` (фронтенду `.env` не обязателен —
в dev работает прокси Vite на `/api`).

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | строка подключения PostgreSQL |
| `REDIS_URL` | Redis. Если недоступен — fallback на in-memory (dev) |
| `JWT_SECRET` | секрет подписи токенов |
| `ACCESS_TOKEN_TTL` / `REFRESH_TOKEN_TTL` | время жизни токенов |
| `ENABLE_REMINDERS` | включает планировщик напоминаний (push/email) |
| `RESEND_API_KEY`, `EMAIL_FROM` | email-отправка (Resend). Без ключа письма логируются в консоль |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Web Push (VAPID-ключи) |
| `FRONTEND_URL` | origin фронтенда для CORS |

```
        ├── layouts/        # sidebar + bottom-nav
        └── pages/          # все страницы приложения
```

## Технические заметки

- Пароли хешируются **bcrypt**; access-token (JWT, 15 мин) + refresh-token (в Redis/in-memory).
- Валидация входных данных на бэкенде — **zod**, на фронтенде — нативные атрибуты форм.
- Даты передаются строками `YYYY-MM-DD` (локальный день клиента).
- Стрики считаются по запланированным дням с учётом лимита пропусков в месяц.
- Экспорт — один CSV-файл с секциями habits/entries/categories.
- PWA и офлайн-режим не реализуются (по ТЗ — обычный адаптивный сайт).
